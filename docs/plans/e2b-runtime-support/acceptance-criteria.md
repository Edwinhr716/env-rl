# E2B runtime support: acceptance criteria

Status: proposal, 2026-11-09, against `e2b` 2.63.0, `e2b-code-interpreter` 2.11.9 and envd 0.10.2.
Group V was checked on Kind on 2026-11-11. The `PR` statuses were checked on 2026-11-12 against #364
at `746d2471` and #365 at `2e8efa07`; `main` (`915894b6`, 2026-11-13) has none of them. The plan is
in [README.md](./README.md).

Status values: **met** (on `main`, with the tests named), **PR** (an open pull request meets it),
**open** (planned, no pull request), **not planned** (decided against; see README.md section 4.3).

Ids run `E2B-1` to `E2B-33` in document order; `E2B-34` to `E2B-36` came later (decision D-9) and
are in groups L, R and P. The letter in a section title names the group and is not part of the id.
"The program" is a script that uses only the public E2B Python SDK and differs from its E2B version
by the import line.

| ----- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------- |
| E2B-1 | envd from the layer starts under gVisor with `-isnotfc -no-cgroups` in two unrelated images (one glibc, one musl), starts a process in each, and the guest's `/readyz` gates on it. The template adds the capabilities of README section 4.1.                                                                                     | PR #364 |
| E2B-2 | After a suspend and a resume, and after a restore from a golden snapshot, envd starts a process, lists processes and delivers watch events.                                                                                                                                                                                       | PR #364 |
| E2B-3 | `/init` sets a default user that exists in the image, and commands run as that user in the default working directory; without `/init` they run as root, and one call can name another user.                                                                                                                                       | PR #364 |
| E2B-4 | The behaviour of a second `/init` is recorded, and an envd without a token is not reachable by a caller without the API token.                                                                                                                                                                                                    | PR #364 |

Checked by hand on 2026-11-11 (README section 5, item 4); a test comes with the live E2E test of pull request 3. | open    |

## Layer and templates (L)

| ID     | Criterion                                                                                                                                                                                                                            | Status  |
| ------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------- |
| E2B-6  | The layer image is built from a pinned `e2b-dev/runtime` commit with a checked sha256, is digest-pinned in the template, and carries envd's licence.                                                                                 | PR #364 |

## Lifecycle (C)

| ID     | Criterion                                                                                                                                                                                                                                                                                                         | Status  |
| ------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------- |
| E2B-9  | `Sandbox.create()` returns only after envd answers and `/init` succeeds. A failure after the create deletes the environment.                                                                                                                                                                                      | PR #365 |
| E2B-10 | `with Sandbox.create() as s:` deletes the environment on exit, also when the body raises.                                                                                                                                                                                                                         | PR #365 |
| E2B-11 | `kill` returns `True`, and `False` for an environment that is gone, in the instance form and in the `Sandbox.kill(sandbox_id)` form.                                                                                                                                                                              | PR #365 |
| E2B-12 | `pause` reads `GetEnvironment`, suspends durably, and returns `False` when the environment is already suspended; `mode="filesystem"`, `keep_memory=False` and `strict=True` raise `SandboxException`. `Sandbox.connect(sandbox_id)` in a new process resumes it with files in place; `on_resume="reboot"` raises. | PR #365 |
| E2B-13 | `get_info` maps the environment status to E2B's states and reports the template. `is_running` reads `GetEnvironment` first, never wakes a suspended environment, and is `False` after `kill`.                                                                                                                     | PR #365 |
| E2B-14 | The sync class dispatches through `LoopRunner` and works when called from a thread and from inside a running event loop's executor.                                                                                                                                                                               | PR #365 |
| E2B-15 | The endpoint, token and atespace come from `SUBSTRATE_ENV_API`, `SUBSTRATE_ENV_AUTH_TOKEN` and `SUBSTRATE_ENV_ATESPACE`. No `E2B_API_KEY` is needed.                                                                                                                                                              | PR #365 |

## Data plane, inherited from the SDK (D)

| ID     | Criterion                                                                                                                                                                                                                                                                                        | Status |
| ------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------ |
| E2B-16 | `commands.run` returns `CommandResult`; a nonzero exit raises `CommandExitException` with the output; `timeout` raises `TimeoutException`. On a deleted or crashed environment the call raises `SandboxNotRunningException`; during a wake it waits and then succeeds (README section 4.2, D-8). | open   |
| E2B-17 | `commands.run(background=True)`, `list`, `connect`, `kill`, `send_stdin` and the `on_stdout` and `on_stderr` callbacks work, with the same behaviour on a gone or waking environment.                                                                                                            | open   |
| E2B-18 | `envs` from `create` reach each command; the `envs`, `cwd` and `user` of a call override them.                                                                                                                                                                                                   | open   |
| E2B-19 | `files.read` (text, bytes, stream), `write`, `write_files`, `list`, `exists`, `get_info`, `remove`, `rename`, `make_dir` and `watch_dir` work. On a gone environment `exists` and `read` raise `SandboxNotRunningException`, not `False` or `FileNotFoundException`.                             | open   |
| E2B-20 | `pty.create`, `send_stdin`, `resize` and `kill` work, with the same behaviour on a gone or waking environment.                                                                                                                                                                                   | open   |
| E2B-21 | With an API token, envd rejects a call without the derived access token, and the API token never reaches envd or a URL.                                                                                                                                                                          | open   |
